Status: **failed under the pre-registered rules**, 2026-10-23. The missed
threshold now passes; the false-invalidation threshold does not. Under one
sensitivity analysis both pass, as described below. Symbol level does
**not** enter the recommended configuration on this evidence. This report

## Design (fixed before labelling, `d87e748`)

ADR 0012 §9 r0.7, SPEC v1.6.6.

- **Predictor.** Walk 3: a symbol fires when its span or its same-file
  context (the items it names) changes, or when it breaks.
- **Repositories and commits.** The same three repositories and 1,000
  commits as the first run.
- **Symbols.** Ranks 6–10 per file, disjoint from the first run (the
  training set): 53 symbols. ripgrep has 38, fd 10 and click 5.
- **Pairs.** Only pairs whose symbol is live at the parent: 1,251.
- **Automatic check.** The replay disagrees with the blob recomputation 0
  times, and no host file has a parse error.
- **Sample.** Same strata, 35 per stratum: 287 pairs, because click's fired
  stratum has only 8.
- **Labels.** Nine new blind agent labellers. Totals: 25 `y`, 262 `n`, 0
  `unsure`; 266 high and 21 medium confidence.
  [`labels.tsv`](p5b-g6-r2/labels.tsv) has each label's labeller, confidence,
  rationale and evidence SHA-256;
  [`evidence.json.gz`](p5b-g6-r2/evidence.json.gz) is the evidence bundle.
- **Thresholds.** FI ≤ ½ × file FI, and missed ≤ file missed + 2 pp, on
  weighted point estimates.

## Why

- **Missed invalidation is solved on fresh data.** The first run's gap of
  +13.1 pp is now +0.0 pp. No invalidating pair was missed where the host
  changed.
- **Pure moves dominate false invalidation.** ripgrep's fired stratum is 38
  symbols broken by one commit, `fdd8510` ("move all source code in crates
  directory"), which moved every file with identical code. The labelling
  rule calls such moves `n`, so all 35 sampled pairs are false invalidations.
  They carry about half of the fired population's weight. Counting moves as
  invalidating instead gives 18.7 %.
- **Same-file context adds a few false invalidations.** Walk 3 fired 9 pairs
  on context alone. Most are `tests::tokens_with_basename`, which mentions
  `CommandSet` and `ExecutionMode`; their edits (an `Eq` derive, a generic
  argument) did not change what the test checks. Span only, the FI would be
  66.7 % instead of 70.4 %.
- **Behaviour-preserving rewrites remain.** Examples are clippy edits (a
  dropped `&`, `unwrap_or` → `unwrap_or_else`), `%` → `format` → f-strings,
  and a semicolon discarding a new return value.
- **One normaliser gap.** P5B-G6R-211: rustfmt reflowed a `where` clause
  and added a trailing comma, and the span changed. The walk drops a
  trailing comma only before a closing bracket, and a `where` clause ends
  before `{`. This is a T45 gap to close in a later walk revision; it is not
  changed here.

## Labelling inconsistency (disclosed)

The batch template, generated by `symbol_replay batches`, listed "removed or
renamed" under `y`. The labeller prompt said a pure move or rename with
identical code is `n`. Both runs used both texts. Labellers mostly followed
the prompt:

- first run: Broken pairs 38 `n` and 3 `y`;
- retest: 38 `n` and 6 `y`.

One labeller flagged the conflict. The "moves invalidating" variant shows the
other reading. The template is now fixed to match the prompt.

## Limitations

- These are agent labels, not human ground truth.
- The sample is small. click's fired stratum has 8 pairs; ripgrep's fired
  stratum is a single commit.
- Few invalidating pairs exist outside fired strata: 1 of 210, so missed
  rates rest on very few positives.
- The verdict turns on one convention (whether a pure move invalidates) and
  on one repository-wide move. The three repositories' supported anchor files
  have few symbols left beyond rank 10, so a third disjoint sample here would
  be smaller still.
