## G5 — Budgets

Initial ADR-calibrated budgets, measured with the workload and fsync/copy-on-write costs reported:

- Import 10,000 entries into the replica in ≤60 s on the remote Linux host.
- Join 10,000 entries with 10 open branches in ≤120 s; report copy-on-write memory.
- Catch up one entry on 10 open branches in ≤50 ms; report op_log batches, fsyncs and memory.
- Publish ten proposals to a local remote with ≤2 s added to `git push`.
- Add ≤20 ms to `git commit` through `reference-transaction`; a team-ref fetch's durable announce and ACK add ≤50 ms.
- Compact and join 100 MiB of team state; report time and peak memory, including the streaming verification buffer separately from resident state.
- Recall p99 with 10⁴ mirrors stays within +10% of the baseline with the same record count.

## G6 — Real use

First use two clones, two signing keys and a bare remote on one machine. Then use a real team remote with agents on both edges for **at least five days**, **at least 50 accepted entries** and **at least two members**. Record:

- Equal team digests checked daily.
- Zero lost proposals: each ends accepted, rejected, conflicted or dropped.
- Probe records depending on every changed team record, read after each fetch: every supersede/retraction invalidates the other edge within one fetch.
- Zero code pushes blocked by publish or ReplicationLag under the default policy.
- No ReplicationLag persisting beyond one fetch after the last import.

## Implementation notes

Clarifications made while implementing milestone 1. They fix details the ADR and SPEC leave open and do not change any guarantee.

- **`Ref` names its revision.** A team rule's reference is `Ref(content)`, like `Pin(content)`: the kernel's `Ref` edge targets a revision, and a rule's identity must not depend on the replica's state.
- **Genesis carries a `batch`.** Generation 0's first entry has the ordinary tree with one proposal whose only op is `SetTeamAccess{doc}`; it is signed by an admin of that document. Every entry is parsed the same way.
- **The Compact reserve is a proven bound.** Where the future `Compact`'s accepted id lands among the sorted items changes the next-fit chunk packing. Next-fit gains at most one chunk when one item is inserted anywhere, so an ordinary proposal is accepted only if `ckpt_size(Σ) + item(64-byte member) + 44 ≤ state_bytes` (one item and one index entry). Then `ckpt_size(Σc) ≤ state_bytes` for every `Compact`, whatever its id and author.
- **git ≥ 2.44 for partial clones.** `ctxd` reads team objects with `GIT_NO_LAZY_FETCH=1`, so a partial clone reports missing blobs (`ReplicaIncomplete`) for the hook to fetch by id in the user's environment (§8.1). Older git ignores the variable and would try the promisor itself, without credentials or a terminal; it fails instead of hanging, and the import stays incomplete until a newer git or `ctx team sync` fetches the objects.
- **The decision log is the replica's durable form.** `<data>/teams/<id>/log` holds every decided entry with the bytes `accept` read, framed and checksummed; open replays it through `accept` (deterministic), cuts a torn tail, and import fetches what is missing from git. Snapshots of the replica (the checkpoint encoding) are a later optimisation, measured against the G5 join budget.
- **Admission details the SPEC leaves open (milestone 3).**
  - A mirror as a local rule's conclusion is `ReplicaReadOnly` (SD21.7 and the §6.2 P10 order), checked before the canonical rule checks; §2.5 A1's `ForbiddenConclusion` wording is superseded for replica origin.
  - No artifact of any type may target a mirror (`ReplicaReadOnly`), not only Conflict sides: only the replica channel writes mirror state, and an artifact a merge carried could otherwise land where its target is invisible. The P7 judge targets the local side.
  - "Rebind target" means a rule whose conclusion is a mirror. Rebinding a local dependent onto a newer mirror head is the intended recovery for `Cur` (ADR §5.3).
  - A replica-origin create outside its own team's namespace is `InvalidKey` (key) or `InvalidLane` (lane). ReservedNamespace applies in the multi-branch kernel only; the team replica's plain `Db` keeps its `team/` keys with Local origin and its own A5.
  - `gap = true` on a scope that is not `team:` is `ChannelRestricted`. The replica channel may not run `ExpectHeads`, branch ops or merges (`ChannelRestricted`).
  - The shred exemption also skips `MissingBlob` for a replica write of shredded content: its bytes are gone, and the revision reads unavailable.
  - A replica `SetMetadata` with non-empty `dirs` is `InvalidMetadata`: only tags are mirrored (Q9).
  - The kernel does not check that a replica batch's principal is the store owner; no client socket maps to `Channel::Replica` (transport trust, as for the observer).
