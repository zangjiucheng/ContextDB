Implementation milestones:

1. **Done.** Projection health:
   - `IndexState` in `ctx_recall`, `ctx status` and MCP;
   - the bounded wait (MCP default 200 ms), which wakes on the indexer's progress;
   - `ctx reindex` (admin), a chunked rebuild that reports `Rebuilding{done, total}`, and `Failed` with a retry;
   - abstract and outline columns, rendered from the whole payload and rebuilt when `LEVELS_VERSION` changes;
   - `contextdb-model::levels`;
   - protocol 6.

   Tests: T56, T86 and T94 (`p8_index`), and T87 (`t87_levels` at 10,000 seeds, plus the stored-copy check). Without a wait, 30 of 30 recalls right after a commit reported `Lagging`.
2. **Done.** Ranking:
   - eligibility (head, lane, `kinds`, `dir`, certification) is decided inside each ranker, before any cut;
   - withheld entries are capped at `limit` and never take an item slot;
   - the key ranker stops at `limit` eligible candidates; bm25 pages the AND query, then the OR query, in pages of `limit × 4 + 16`;
   - RRF fusion (k = 60) with the exact key first, then ties by key rank and logical id;
   - `dir` covers the logical's `dirs` metadata, the revision's anchor premises, and an anchor's own path;
   - structured MCP `scope` (`{lane, kinds, dir}`) or a plain lane string;
   - `limit` above 100 is clamped and reported as `limit_clamped`.

   Tests: T54, T85 and T95 (`p8_ranking`), T85 `dir` through anchors (`anchors`), the fusion unit tests (`ranking`), and MCP scope parsing. Changed: the P3 test that ranked every key match before every text hit now checks RRF (exact key first), and t44 now looks for `root-a` by key (the OR query also finds `root-b`).
3. **Done.** Levels and packing:
   - `ctx_recall{level, budget_tokens}`: greedy packing in fused order (`packing.rs`). The header is charged first (16 tokens plus the key's bytes/4). Each item gets the highest level that fits, from `full` down to the header alone. Packing stops when a header no longer fits; the rest are counted in `omitted`, with no handle, certificate or ledger entry. `estimate: "bytes/4 v1"`.
   - Without a level or a budget the response keeps the header-only shape.
   - `ctx_read{level}` (default `full`) recomputes the rendering from the payload; below `full` there is no payload.
   - Every rendered item carries `level` and `cut`.
   - `LedgerEntry.level`: a re-read of the same revision merges by max.
   - Session log format 4: `full` reads keep tag 15, and levels below `full` use tag 22. Format-3 read events decode as `full` (SPEC v1.8.1 correction).

   Tests: T55 and T88 (`p8_levels`), the rendering check (`levels_render_like_the_pure_functions`), `p8_leveled_reads_need_format_4` (`session_log`), and the packing unit tests.
4. **Done.** Summaries:
   - `Item.premises{moved, total}` on every Summary, from its witness rule against the nearest Verified vector (SPEC v1.8.2 note);
   - shown by `ctx_read`, `ctx_recall` (withheld headers included) and MCP (`premises`, plus a `note` when `moved > 0`);
   - the briefing lists up to 16 Summaries with moved premises.

   The early stop needed no new code. Reverting a premise to validated content brings back the same revision, so discovery queues nothing and no record is written; re-recording identical text is an empty `Committed`. The `ctx_supersede` reply is pinned in SPEC §6.3. Tests: T90 (`p8_summaries`, and `t90_reverting_to_validated_content_queues_nothing` in `p7_jobs`), and the briefing rendering (`hook_details`).
5. Embeddings, with the P7 m4, m6 and m7 fixes (T89, T93).
6. Git mirror (T57, T91, T92, T96, T97).
7. Verification (G3–G8, G6).
