## Decisions (owner, 2026-11-06)

F1–F13 take the recommended option (a):

- **F1** one principal per OS user, mapped from the peer uid by a committed access document.
- **F2** the default lane is unchanged; each lane names its curators.
- **F3** crypto-shred through one key per content hash in an append-only key log; `ctx migrate` re-encrypts existing packs.
- **F4** the signed log head is deferred to its own ADR.
- **F5** G6 runs with two OS users on macOS (and Linux if the remote host allows).
- **F6** personal lanes do not egress by default; validators marked `local = true` are exempt.
- **F7** a merge needs authorisation (`MergeUnauthorized{count}`).
- **F8** non-owner principals use MCP only in P9.
- **F9** `ctx ui` uses a per-launch token in multi-user mode.
- **F10** proof of possession: non-owner commits carry the bytes of every content hash they introduce.
- **F11** branches record their creator.
- **F12** the store owner sees everything.
- **F13** a principal holding the exact bytes may learn they were shredded.

**F14**, in the owner's narrowed form:

- A merge into the merger's own branch transports every mergeable change; reads still go through the ACL.
- A merge into `main` or a branch the store owner created needs the store owner for an actual Policy change.
- ValidationRecords keep their exact `(rule, curvec)` and their original validator source.
- CodeAnchor objects arrive not base and `unobserved`.
- Every other change is checked as its direct op: Curate, rule premises, artifact targets.

## Implementation milestones

See ADR 0017 §13.

1. **Done.** Principals and transport (ADR 0017 §3; T58, T98, T99).
   - **Reserved ids** (`PrincipalId::is_reserved`, `is_store_owner`): 0–15 and `0x5641_xxxx`. Document ids start at 16.
   - **The uid mapping** (`principals::PrincipalMap`): the store owner's uid gets the socket's channel principal, as before. A mapped uid gets its principal, on the agent socket only. Any other uid is closed before a byte is read.
     - The mapping is checked again on every request; a revoked or remapped uid gets `AccessRevoked` and the connection closes.
     - In milestone 1 the mapping is set by `Daemon::set_principals`; milestone 2 feeds it from the committed access document.
   - **Socket layout:**
     - `run/shared/agent.sock` (directory 0711);
     - `run/private/{observer,admin}.sock` (0700);
     - the public `run/shared/endpoint` record (0644: protocol, socket name, owner uid).
     - The agent socket is 0600 in single-user mode and 0666 once another principal is mapped.
   - **Entering multi-user mode** (`set_principals`) first requires the file-system rules (`contextdb-proto::fsguard`):
     - every entry owned by the daemon's uid, private modes, and no ACL (deny-only included);
     - the ancestors owned by root or the owner and not writable without the sticky bit;
     - every mapped uid able to search down to the shared socket;
     - the sockets inside `<data>` (the long-path fallback is refused).
     - Violations are returned by name, and the agent socket stays closed.
   - **File modes:**
     - the store layer and the outbox create directories 0700 and files 0600 explicitly;
     - `ctxd`, `ctx`, `ctx-hook` and `ctx-mcp` set `umask(077)`;
     - the launchd plist has `Umask = 63` and the systemd unit `UMask=0077`;
     - `ctx doctor <dir> --fix-modes` repairs modes and strips ACLs (macOS through `exacl`, Linux through the POSIX ACL xattrs, so no libacl is needed), and never changes an owner.
   - **Clients:** `Client::connect_shared` (and `ctx-mcp` for a data directory the caller does not own, `--data` or `CTXDB_DATA`) reads the endpoint. Before sending anything it checks that:
     - the endpoint's owner uid equals the owner of `<data>`;
     - the ancestors pass the ownership rule;
     - the socket's peer uid is the owner.

     Otherwise `ServerNotOwner`.
   - **The non-owner allowlist** (`service::non_owner_allowed`): the requests `ctx-mcp` sends. Everything else is `ChannelRestricted` (`Status`, hooks, observer and admin requests).
   - **Sessions and handoffs:**
     - sessions are bound only by their principal: `SessionOfAnotherPrincipal` for session ids and claimed call ids;
     - harness keys are per principal, also after a restart;
     - `ctx_handoff_begin{to}` names the accepting principal; unnamed handoffs stay within the sender's principal;
     - listing and accept show only handoffs addressed to the caller;
     - the accept reports `dropped_unauthorized` and validates only what it copied.
   - **Protocol 7.**

   Tests:
   - `p9_transport`: T58; T98 (layout and modes, SQLite's `-wal` included; mapped, unmapped, revoked and remapped uids through the debug-build peer-uid hook; modes, inherited ACLs, an unsafe ancestor, the long-path fallback; forged and malformed endpoints); T99 (bindings, harness keys across a restart, addressed handoffs across a restart).
   - `p9_allowlist` (`contextdb-mcp`): every `ctx-mcp` tool, driven as a non-owner, sends only allowlisted requests.
   - `fsguard` unit tests, and the session-log test for tag 23.

   **Deviations from ADR 0017 and open items:**
   - **The session log gains one event tag inside format 4.** An addressed `HandoffBegin` (sender or recipient not the store owner) is tag 23. An unaddressed one keeps tag 20's bytes. ADR 0017 §10 said the session log is unchanged. No format bump is needed, because a P8 binary cannot open a P9 store anyway (op_log format 5).
   - **Ancestor ACLs are not evaluated.** The ancestor check reads modes and groups (`id -G`), not ancestors' ACL denies (§3.2 calls it best effort). G6's real two-user run is the authority.
   - **Multi-user mode is not reachable outside tests yet.** Milestone 2 maps principals from `SetAccess`. Until milestones 3 and 4 add read redaction and write authorisation, a mapped principal would see and write everything, so milestone 2 must not let a deployment enter multi-user mode before then.
   - **`TxnStatus` for non-owners:** "own rows only" (§5.5) lands with the read redaction in milestone 3.
   - **`may_read`** (handoff filtering) is the milestone 3 stub and allows every read.
2. **Done.** The access document (ADR 0017 §3.1, §4).
   - **`Op::SetAccess{doc}`**, op tag 20, **op_log format 5**:
     - admin only (`ChannelRestricted`), the sole op of its batch (`SoleOpRequired`), committed on `main`, global to every branch;
     - never in a dry run, and not on another branch (both `InvalidAccess`);
     - kernel state, rebuilt by replay and carried by format-5 snapshots.
   - **Validation** (`contextdb-core::access::validate`): every rule of §4.2 that needs no daemon state gives `InvalidAccess{reason}`. The daemon adds the owner-uid rule before the kernel (the owner entry must carry the daemon's uid), whether the document comes through `SetAccess` or a raw admin batch. `ctx_commit` and `ctx_what_if` refuse it (`InvalidRequest`).
   - **Principal ids** (`AccessState::apply`): new names get ids from 16 upwards, in sorted order within a document. Ids are never reused, a name keeps its first id, and the owner's entry maps to 0.
   - **`Authorized(p, l, b)`** (`AccessState::authorized`): the five steps of §4.4 over `entry(lane)` (§4.3). It returns the decision and the deciding step. A grant dir covers a `dirs` entry that is equal to it or below it.
   - **The independent reference** (`contextdb-oracle::AccessModel`): validation, ids, and `Authorized` as a decision table. `BranchOracle` applies `SetAccess` with the kernel's error order.
   - **The daemon:**
     - `Request::SetAccess`, `AccessShow` and `AccessCheck` (admin socket);
     - the mapping (`principals::map_of`) applied at start and after every `SetAccess`, through the file-system gate (`principals::MultiUser`), and only when `Options::multi_user` is set;
     - with multi-user mode enabled, a `SetAccess` that maps another uid is refused before it commits while the rules fail, a start is refused (`StartError::MultiUser`), and any failure falls back to single-user mode.
   - **The CLI:** `ctx access apply|show|check`. `access.toml` is parsed with unknown keys refused, defaults filled in (`code_lanes` readable by members and written by the owner, `default_lane` owner only, `[personal] egress = false`), and the owner entry found by the caller's uid.
   - **Migration:** `ctx migrate` accepts format 4: the header-only rewrite keeps batches, hashes and frame checksums. EventLog v3 carries tag 20.

   Tests:
   - `contextdb-testkit` `p9_access`:
     - wire and EventLog v3;
     - kernel and branch oracle on admin, sole, main and dry-run refusals;
     - 17 validation cases through both;
     - id assignment (leaving, rejoining, owner rename, refused switches);
     - `Authorized` step by step against ADR §4.4;
     - PROP15 for M2: random documents (valid and invalid) and random logicals. Kernel and oracle agree on acceptance, ids and every decision with its step; 2,000 seeds by default (`CONTEXTDB_P9_ACCESS_SEEDS`), and 20,000 seeds were run.
   - `contextdb-store` `p9_access_log`: replay and snapshot, and format 4 → 5 byte-identical. `migration` now targets `log::FORMAT_VERSION`.
   - `contextdb-daemon` `p9_access`:
     - owner-uid and channel checks;
     - `AccessShow`, and `AccessCheck` per branch and its errors;
     - without multi-user mode nobody is mapped;
     - with it the mapping follows `SetAccess`, revocation and restart;
     - the file-system gate on `SetAccess` and at start.
   - `ctx` unit tests: the ADR §4.1 example parses; unknown keys and a missing owner are refused.

   **Deviations from ADR 0017 and open items:**
   - **`ctx migrate` 4 → 5 is the header-only rewrite for now.**
     - The completion procedure of §10 (the `MIGRATING-5` marker, re-encrypted packs, rebuilt projections, disk verification) lands with crypto-shred in milestone 6.
     - A store migrated by a milestone-2 build is at format 5 with plaintext packs and no marker. Milestone 6's open check must refuse it (`MigrationIncomplete`), and its rerun must handle "format 5, no marker" by running steps 3–7.
     - The three deployments stay on their P8 build and are not migrated unless the owner asks.
   - **`AccessDoc` carries `owner`**, the name of the owner's entry. `ctx access apply` fills it from the caller's uid, and the daemon checks it against its own. The kernel is pure, yet id assignment must know which entry maps to 0.
   - **A name cannot switch between the owner and another principal** (`InvalidAccess`). Otherwise a former owner name could later bring a different uid in as principal 0. This follows from §3.1 ("a name always maps to its first id"); §4.2 does not list it.
   - **Grants as well as denies may name `@group`.** §4.4 says denies apply "directly or through a group"; grants are read the same way. A subject must name at least one principal, and every principal it names must be a member.
   - **Code-lane writers** may be `*owner` or the owner's name; any other principal after expansion is refused. An empty lane name is refused too.
   - **The wire form of `AccessDoc` is binary and canonical** (sorted maps and sets, like `PolicyDoc`'s wire form), not inline JSON. It is canonical by construction.
   - **Visibility (step 3) never decides** while personal entries are synthesised: a principal is never a member of another's personal lane, so membership refuses first. The step is kept, as §4.4 says. PROP15 checks that it is unreached.
   - **Multi-user mode needs `Options::multi_user`.** `ctxd` never sets it in this milestone. Read redaction (milestone 3) and write authorisation (milestone 4) must land first.
   - **`ctx access check`** answers only for principals the current document lists. `AccessShow` and `AccessCheck` are admin-socket only.
3. **Done.** Reads (ADR 0017 §5).
   - **The redaction point** (`contextdb-daemon::redact`): `Service::handle` sends every response to a principal other than the store owner through `Viewer::redact`.
     - The viewer judges `Authorized(p, l, b)` once per logical, through `BranchView::authorizes` (the kernel's access document, the branch's `dirs`). A rule is whole only if its conclusion, premises and references are all visible.
     - The branch is the one the request reads: the bound session's, the one `OnBranch` named, or the one `ctx_changes` resolved. Ids are resolved on the newest snapshot, so a commit's own allocations are found.
     - The pass is total: a response type a non-owner cannot receive becomes `ChannelRestricted`. The store owner's responses are returned as they are, with no `redaction`.
   - **Filtered where computed**, because they leave a trace:
     - `ctx_read`, `ctx_why`, `ctx_why_not` and `ctx_impact` of a hidden logical answer `Unavailable{target}`, with the target as sent and no ledger entry;
     - recall's `admit` checks authorisation first, so a hidden match takes no slot and is never withheld;
     - certificate issuance refuses an unauthorised entry (`NotCertified{Unavailable}`), and `validate_certificate` returns `Denied` when an entry is no longer authorised (T101);
     - handoff `may_read` is the real check;
     - `TxnStatus` answers only for rows of the caller's principal: the store's `TxnStatus::Committed` now carries the row's principal.
   - **Shapes (protocol 7):**
     - `Response::Unavailable{target}`;
     - `Envelope.redaction: Option<Redaction>`, holding `redacted`, `redacted_references`, per-node `NodeRedaction{rev, rule, premises, rules}` and `vector_size` per certificate id;
     - `Witness::Redacted` and `StaleReason::SupersededPinnedPremiseRedacted`, which appear only in responses and are never computed.
   - **`ctx ui`:** a launch token while the access document maps other principals. It is printed in the URL fragment, kept in `sessionStorage`, sent as `Authorization: Bearer` and checked in constant time; a foreign `Origin` is refused and no cookie is used. `recall.sqlite` abstracts are used only before any access document exists.
   - **`ctx-mcp`:** `{key, status: "UNAVAILABLE"}` and a `redacted` object in tool results.

     - T17b: WHY with a redacted witness, one hidden premise and one rule whose premises are all hidden; WHY_NOT and IMPACT counts; UNAVAILABLE targets.
     - T100: Diff, `ctx_changes`, `TxnStatus` per principal and withheld error details on a live service; a pure sweep over every list-bearing response type, including certificates and verdicts, merge reports, feeds, items, errors and the store owner.
     - T101: a revocation makes a cert-id check and the ledger's check `Denied`, and later reads UNAVAILABLE.
     - Handoff `dropped_unauthorized`.
     - **PROP15, read half:** random `generate_p7` histories spread over shared, personal, code and unlisted lanes, with four creators, `SetMetadata` dirs and a second document in the middle. Random valid documents with groups, grants, denies and `*writers`. For every principal (mapped, owner-reserved, unknown):
       - the viewer equals `AccessModel`;

   - `ctx` unit tests for the launch token (401 without it, with a wrong one or as a cookie; 403 for a foreign `Origin`; the static page open); `contextdb-mcp` UNAVAILABLE rendering and counts.

   **Deviations from ADR 0017 and open items:**
   - **Counts travel in the envelope**, not inside each response type. Commit results, merge reports and certificates are durable values, and their encodings stay unchanged; one `redaction` record per response carries what §5.4–§5.6 count.
   - **WHY lists a rule when at least one of its premises is visible**, without the rule's other premises. Explanations name rules, not their premises. Per-rule premise counts are given for the witness rule, whose premise proofs are the only ones shown, and for WHY_NOT failures.
   - **WHY, WHY_NOT, IMPACT and Diff are not made bound requests** (§5.4, §5.5). Redaction keys off the connection's principal and the branch the request reads (`OnBranch` or a bound session), which gives the same guarantee without changing the requests `ctx-mcp` sends.
   - **Error details are withheld wholesale for non-owners**: the code stays, and the detail becomes fixed text except for a short list of codes whose detail names nothing. The finer mapping of §5.7 (echoing the caller's own refs, `CycleDetected` nodes with a count, `MergeNotCertified{redacted}`, `Unauthorized`) lands with write authorisation in milestone 4, which is where those errors arise.
   - **`Validation::Ambiguous` on a hidden logical** names `REDACTED_LOGICAL` (`u32::MAX`, never a real id).
   - **Kept as counts:** `MergeReport.newly_visible` and `convergent`. `Validation::Unknown{lag}` keeps its code-lane scope names.
   - **Nothing to redact:** `Item` has no `anchors` or Conflict pointer field (§5.2), and the briefing and Stop report are store-owner requests (§3.3).
   - **`validate_certificate` checks `Denied` after `BranchMismatch`.** A certificate from another branch is judged there; its entries' `dirs` are branch-dependent.
   - **`ctx ui` replays the op_log**, which only the store owner can read (0700/0600), so in practice it is the store owner's viewer and shows everything (§5.10). The token keeps other local users, who can reach 127.0.0.1, out of it. Serving a non-owner through `agent.sock` is not built: a non-owner cannot run the viewer at all.
   - **Vectors only for egress lanes** (§5.3) comes with egress in milestone 5.
   - **Multi-user mode is still not reachable outside tests**: `ctxd` never sets `Options::multi_user` before write authorisation (milestone 4).
