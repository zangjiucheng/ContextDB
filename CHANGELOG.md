# Changelog

## Unreleased

- **OpenCode 2.0 as a third harness** (ADR 0014).
  - `ctx setup --harness opencode` (or `all`) registers the MCP server in `opencode.json` and installs a plugin in `.opencode/plugins/contextdb/`.
  - The plugin sends every event to `ctx-hook opencode <event>`. The same certificate check warns or denies `edit`, `write`, `patch` and `shell`; the briefing and per-turn context reach the system prompt; edits are recorded and drift is reported.
  - MCP calls bind by OpenCode's `_meta["ai.opencode/sessionID"]`.
  - Verified on OpenCode 2.0.32: the model reads the briefing, and `ctxd` holds the session's stream. A gated edit was tested with a fake OpenCode context and through `ctx-hook`, not yet live.
- `ctx ui` follows P5a–P6 and v1.6.11:
  - It replays the op_log with the multi-branch kernel. Before, any log with a branch op failed with `replay diverged`.
  - A branch selector shows one branch at a time, the timeline names each commit's branch, and open Conflict artifacts are listed on their target.
  - `ref` edges are drawn and listed, including reference-only rules ("references only, never supports").
  - Code anchors show their path or `path#symbol`, and the panel decodes the committed descriptor (path, symbol, language, normaliser).
  - WHY and WHY-NOT are trees instead of Rust debug output.
  - Replayed status uses the last committed watermark per anchor scope, and the panel adds the live status from `ctxd` when it differs (for example `PENDING(ObservationLag)`). Bodies of branch-only revisions are read through a viewer session on that branch.
- **Dependency usability** (SPEC v1.6.11), from agents writing to a second repository's store: of 18 `ctx_record` calls in one session 9 were refused, and the agent ended by dropping its deps.
  - A record may carry only `ref` deps. The kernel accepts a reference-only rule and never counts it as support (SD3/SD6, T09w), so the record still needs `adopt_as_base`; `ctx_impact` lists it. `ctx_record` warns when every dep is `ref` and `adopt_as_base` is false.
  - `ref` may name a Summary (A2); `cur`/`pin` on a Summary are still refused.
  - Refused deps say which dep and what to send: a Summary named with `cur`/`pin` asks for `sem` or `ref`, and a bare key gives its current `key@rev`. The `ctx_record` tool description documents the four dep kinds.
  - `ctx_supersede carry_rules=copy` keeps references. Writes whose deps are all `ref` count as writes without deps in the P4 telemetry.
  - An op_log with a reference-only rule cannot be opened by an earlier binary.
- Hooks: the default check budget is 500 ms (was 150 ms; a busy daemon took up to ~340 ms on a real repository). A timed-out check says `ctxd did not answer within N ms` instead of `Io(Os { code: 35, kind: WouldBlock … })`. The "no certified reads" warning is shown once per session and agent instead of every 10 minutes.

- **P5b normaliser walk 4** (ADR 0012 r0.9, SPEC v1.6.10), from the independent implementation review. Fixed:
  - Text no child node covers is now hashed. Before, `"hello\n"` and `"bye\n"` hashed alike in Python, as did f-string text and format specifiers, Rust raw strings and `macro_rules!` separators.
  - A same-file helper, constant or import that does not parse marks the symbols that use it as erroneous instead of giving them a new revision.
  - Python statements in module-level `if`/`try` blocks are separate context items.
  - Go `for` clauses keep their semicolons, and grouped `var ( … )` declarations are symbols.
  - Deep `use` trees no longer overflow the observer's stack.
  - Smaller gaps: JS array holes, multi-declarator `export`/`const` keywords, `export declare`, dotted namespaces, `this.#p` and `r#` names in context, Go `/vN` imports, `import a.b`.

  **Symbol anchors need `ctx anchors migrate`**: 886 of the 6,820 reference symbols re-hash. Formatter equivalence (T45) is unchanged. G6 was rescored on the same labels: FI 17.5 %, missed +0.0 pp under the owner convention; 70.0 % under the pre-registered reading.
- P5b: a symbol anchor that is Missing or Broken during `ctx anchors migrate` no longer leaves later scans refused, and no longer leaves the scope lagging for good. The version check and the `CTXPOS02` header now count live anchors only.
- P5b gate: G1, G7, G8 and the independent review are done. G3 mutation was rerun with `robustness`; every non-equivalent mutant is caught. The phase gate waits on P5a and P4.

- **P6: branches, transactions and WHAT_IF** (ADR 0013, SPEC v1.6.8). Context forks and merges like the code it describes: explicit branches (`ctx branch`, `ctx_branch`; a session binds to the branch named like its git branch), three-way merge with `Conflict` artifacts that gate their target (`CONFLICTED`, SD17; `ctx merge`, `ctx_merge`, `require_certified` by default), atomic multi-op commits with actor-side certificate validation (`ctx_commit` with `expect_cert_valid`, closing write skew, T19), and dry runs of any batch including merges (`ctx_what_if`). **Upgrade**: protocol 4 and op_log format 3; stop `ctxd`, run `ctx migrate <dir>` (keeps `log.v2.bak`, resumable, lists epochs whose recorded result changes under the Conflict gate) and upgrade every binary together.
- P6 independent implementation review (ADR 0013 r0.7, SPEC v1.6.9), 8 majors fixed with regression tests: a default `require_certified` merge now refuses Conflicts off the head; late `InvalidReadSet` in a merge batch no longer double-maps ids (an actor panic); branch digests include the branch entry and received sync points; a strict check on a branch issues from the branch; `ctx_commit` idempotency binds branch, channel and principal and survives a re-issued certificate; group commits write each epoch's projection rows as of that epoch (also pre-P6 for posts and base history); `ctx migrate` reports changed epochs after an interruption; format-3 projections live in `projections.v3.sqlite` so a rollback works. `ctx_branch`/`ctx_merge` accept `client_txn_id`.
- P6 gate runs: G1 caught the branch oracle depending on blake3 (now injected by the caller). G3 adds PROP7 for branch Ops, PROP11, PROP8 and PROP10 per branch and closes the kernel/shared mutation survivors (ValidationRecord merge conflicts were untested). G4's branch stress found two merge defects, both fixed without semantic change (ADR r0.6): the merge-base search was cubic in the number of sync points (60 ms per merge after 2,000 merges, now ~1 ms), and every sync point kept a whole branch database (488 MB after 1,500 merges, now 2 MB), so states that can never be a base are dropped. G2 closes with a service test of T19 where only the watermark moves in the window.

- `ctx setup` now runs `ctxd` through the per-repository login service (launchd / systemd --user) by default, so it starts at login and restarts after a crash. A running `ctxd` is never stopped; without a usable service manager setup starts it detached and says so; `--no-service` keeps the old behaviour.
